# VoiceGateway v0.1.0 — Design Document

**Status:** Locked
**Timeline:** 4 weeks (parallel to OpenRTC-Python v0.1)
**Owner:** mahimairaja
**Scope:** Cost tracking foundation rebuild + framing fixes + LiveKit fallback docs

---

## 1. Summary

VoiceGateway v0.1.0 rebuilds the cost-tracking foundation around `pydantic/genai-prices` as the LLM pricing source, validates streaming cost accounting via a fixture-based test suite, ships first-class reconciliation tooling, and fixes the credibility issues the audit surfaced (framing slip, stale LiteLLM migration doc, missing decision tree). It explicitly does not include runtime fallback engineering — LiveKit's own `FallbackAdapter` already covers that case at the plugin layer; v0.1 ships a documentation guide showing the recommended composition pattern instead.

The wedge reframes from "cost tracking" (which the audit correctly identified as table-stakes vs LiteLLM) to **"modality-aware estimation + reconciliation"** — a narrower, more defensible position that doesn't require beating LiteLLM on feature surface.

## 2. Goals

1. **Stop maintaining LLM pricing manually.** Hand-curated pricing tables drift silently. Adopt `pydantic/genai-prices` (1,100+ models, 33 contributors, monthly releases, historic price tracking) as the LLM pricing source. Keep STT (per-minute) and TTS (per-character) in a local catalog with explicit source-date metadata.
2. **Validate streaming cost accounting without dogfooding.** Build a fixture-based test suite where real provider streaming responses are recorded once and replayed in CI. Every cost path has a test that asserts the calculated cost matches what the provider would charge for that exact response.
3. **Ship reconciliation tooling.** `voicegw reconcile` command + CSV export + per-request pricing-source visibility. Users who care can verify VG's numbers against their actual provider invoices.
4. **Fix the framing problem.** README and docs reposition VG as "the gateway your LiveKit voice agent needs." Stale claims removed. Decision-tree page directs non-LiveKit users elsewhere honestly.
5. **Document the fallback story properly.** A guide showing how to compose VG providers with LiveKit's `FallbackAdapter` for STT/LLM/TTS — the recommended way to deliver the README's "Cloud outage? Switch to local." promise.

## 3. Non-Goals

These are explicitly **out of scope** for v0.1.0. They will not be pursued even if they look attractive during the build:

- **Runtime fallback engineering.** LiveKit's `FallbackAdapter` handles this at the plugin layer. Building VG's own runtime fallback would duplicate functionality.
- **OpenAI-compatible HTTP shim** (`/v1/chat/completions`, etc.). Niche scope; ship LiveKit-native first.
- **Postgres backend, multi-instance scaling.** Validate single-instance demand first.
- **Multi-tenancy / per-project rate limits.** v0.2+.
- **Key rotation tooling.** v0.3+.
- **Dashboard improvements** (filters, exports, time pickers).
- **More providers.** 11 is enough.
- **Launch artifacts** (blog posts, Show HN drafts, screencast scripts). v0.1.0 ships the product; launch is a separate phase that comes after.
- **Per-project / per-request fallback chain configuration.** v0.2+.
- **Validation against real production traffic.** mahimairaja explicitly chose to skip dogfooding as a hard gate. Substitute validation (fixture-based testing against recorded real provider responses) is what we ship instead. v0.1.0's CHANGELOG must explicitly note this limitation.

If a tempting fix surfaces during the loop that isn't in this list, it goes to TODO.md "Discovered work" and gets evaluated for v0.2 — not v0.1.

## 4. The Wedge — Reframed

### Old framing (audit identified as broken)

> "VoiceGateway is a self-hosted inference gateway. We do cost tracking, budget enforcement, fallback chains, observability."

This framing primes readers to expect a LiteLLM-shaped HTTP proxy. They bounce when they discover it's a Python library returning LiveKit plugin instances.

### New framing

> "VoiceGateway gives LiveKit voice agents modality-aware cost estimation backed by `pydantic/genai-prices`, plus reconciliation tooling so you can verify our numbers against your actual provider invoices."

This framing has three properties the old one didn't:

1. **Honest about scope** ("LiveKit voice agents" — not general LLM gateway)
2. **Honest about accuracy** ("estimation" + "reconciliation tooling" — not "we calculate your costs perfectly")
3. **Defensible** — neither LiteLLM nor Helicone nor Portkey ships modality-aware estimation + reconciliation tooling for voice workloads. The combination is narrow enough to be uncrowded.

The disclaimer that comes with this framing — "LLM costs are estimated via genai-prices, may drift up to 5%; reconcile against your provider invoice for FinOps-grade accuracy" — is *better* than the current product (which has no disclaimer at all on stale numbers).

## 5. Architecture

### 5.1 Pricing source split

```
voicegateway/pricing/
├── llm.py              # Wraps pydantic/genai-prices for LLM
├── stt.py              # Local catalog, per-minute, source-date tagged
├── tts.py              # Local catalog, per-character, source-date tagged
└── catalog.py          # Unified facade — dispatches by modality
```

`CostTracker.calculate_cost()` dispatches by modality:
- `modality == "llm"` → `pricing.llm.calculate(model, input_tokens, output_tokens, ...)` — calls into genai-prices
- `modality == "stt"` → `pricing.stt.calculate(model, audio_seconds)` — local catalog
- `modality == "tts"` → `pricing.tts.calculate(model, character_count)` — local catalog

Each `RequestRecord` gains a `pricing_source: str` field — `"genai-prices@0.0.52"` for LLM, `"voicegateway-catalog@2026-05-03"` for STT/TTS. Surfaced in `/v1/costs`, `voicegw reconcile`, and the dashboard.

### 5.2 Streaming validation strategy

Existing `InstrumentedSTT|LLM|TTS` wrappers count units (tokens/seconds/chars) across streaming chunks. The audit found that no test verifies this works correctly for streaming responses — only batch.

**The fix** (without requiring dogfooding):

A new `tests/fixtures/streaming/` directory with recorded real provider responses:
- `tests/fixtures/streaming/openai_gpt4omini_stream_001.json` — actual response from `gpt-4o-mini` streaming, with timestamps, chunks, and the provider's reported usage at end-of-stream
- One fixture per provider per model per modality, ~5-10 fixtures total
- Recorded once via `pytest --record-fixtures` (a new dev-only script that hits real APIs and saves responses)
- Played back in CI via `respx` or similar HTTP mocking

For each fixture, an integration test asserts:
1. VG's wrapper counts the same number of input/output units the provider reported in the final usage block
2. VG's calculated cost matches what `genai-prices.calc_price(model, recorded_input_tokens, recorded_output_tokens)` returns
3. Per-chunk timing data is correctly captured (TTFB, total latency)

This is **substitute validation** — not as good as dogfooding, but it catches the high-frequency bugs ("token counter off by one in streaming," "TTFB hooks fire too late") without requiring real production traffic.

### 5.3 Reconciliation tooling

Three deliverables:

**`voicegw reconcile` CLI command:**
```
voicegw reconcile \
  --provider openai \
  --start 2026-04-01 \
  --end 2026-04-30 \
  --provider-usage-file openai-april-usage.csv \
  [--format text|csv|json]
```

Reads VG's logged costs for the period, reads the provider's usage export (downloaded by user from provider dashboard), produces a per-model diff table:

```
Model               Provider Cost  VG Cost   Diff      Diff %
gpt-4o-mini         $42.18         $40.91    -$1.27    -3.0%
deepgram/nova-3     $18.42         $18.42    $0.00     0.0%
cartesia/sonic-3    $7.61          $7.94     +$0.33    +4.3%
                                              ----------
                                              Total: -$0.94 (-1.4%)
```

**`voicegw export-costs` CLI command:**
```
voicegw export-costs \
  --start 2026-04-01 \
  --end 2026-04-30 \
  --project tony-pizza \
  --format csv
```

Per-request line items: timestamp, project, modality, provider, model, input_units, output_units, calculated_cost, pricing_source, status. CSV by default, JSON optional.

**`/v1/costs` endpoint enhancement:**
- Add `?per_modality=true` query parameter — returns separate STT/LLM/TTS sums
- Add `?include_pricing_source=true` — adds source attribution to each line
- Add `?start=` and `?end=` ISO date parameters — replaces the fixed `period=today|week|month`

### 5.4 LiveKit FallbackAdapter integration docs

A new page `docs/examples/livekit-fallback-adapter.md` showing the recommended composition:

```python
from livekit.agents import stt, llm, tts
from voicegateway import Gateway

gw = Gateway()

# Compose VG providers with LiveKit's FallbackAdapter
fallback_stt = stt.FallbackAdapter([
    gw.stt("deepgram/nova-3"),       # primary
    gw.stt("groq/whisper-large-v3"), # secondary cloud
    gw.stt("local/whisper-large-v3"), # local fallback
])

# Use in AgentSession as normal
session = AgentSession(stt=fallback_stt, ...)
```

The doc covers:
- How LiveKit's FallbackAdapter detects failures and swaps providers
- How VG's cost tracking interacts with fallback (each attempt is logged separately with status)
- Recommended fallback chain patterns (cloud→cloud→local)
- Why this is better than VG building its own fallback (LiveKit maintains the adapter, ships with the framework, doesn't duplicate functionality)

## 8. Risks

### 8.1 Streaming fixtures go stale

Recorded fixtures capture provider behavior at a point in time. If OpenAI changes its streaming format, fixtures don't auto-update — tests still pass but production breaks.

**Mitigation:** Quarterly fixture refresh task added to v0.2 backlog. Fixture filenames include date suffix (`openai_gpt4omini_stream_2026-05-03.json`). CHANGELOG notes "fixture set last refreshed YYYY-MM-DD."

### 8.2 genai-prices accuracy disclaimer hurts marketing

Their README explicitly says "these prices will not be 100% accurate." Inheriting this disclaimer might feel like a step backwards.

**Reframe:** Today VG has no disclaimer at all — its numbers are silently wrong when prices drift. genai-prices+disclaimer is *more* honest, not less. The reconciliation tooling closes the loop.

### 8.3 No production validation despite shipping

mahimairaja explicitly opted out of dogfooding-as-gate. The substitute (fixture-based testing) catches obvious bugs but not subtle real-world ones (e.g., per-voice tiered pricing in Cartesia that isn't in any documentation).

**Mitigation:** CHANGELOG explicitly says "v0.1.0 cost tracking is validated against fixture-recorded responses, not against real production traffic. Reconcile your numbers against your provider invoice during the first 30 days." This is honest framing that protects credibility if drift is discovered.

### 8.4 Scope creep into "while we're in here"

The pricing rebuild touches `CostTracker`, `RequestRecord`, the storage schema, and `/v1/costs`. Tempting to "also fix" the budget enforcer's TTL window or add per-project pricing overrides.

**Mitigation:** Hard-coded in PROMPT.md scope-discipline rules. Anything outside the §6 deliverable list goes to "Discovered work."

### 8.5 4-week timeline conflicts with OpenRTC-Python v0.1

mahimairaja is running both projects. OpenRTC has a real architectural unknown (50-session benchmark). VG is mostly known work.

**Mitigation:** OpenRTC is the priority. If VG slips, ship Phases 1-2 only as v0.1.0 and defer Phases 3-4 to v0.1.1. The framing fix + genai-prices integration is genuinely useful even without the reconciliation tooling.

## 10. Decision Log

|---|---|
| Adopt genai-prices instead of maintaining LLM catalog | 1,100+ models maintained by 33 contributors with monthly releases. Months of work avoided. Modality split (genai-prices for LLM, local catalog for STT/TTS) plays to each source's strength. |
| Hard dependency, not vendored | Always-fresh prices. Air-gapped users can vendor at deploy time if needed. Reduces VG complexity. |
| Reframe wedge as "modality-aware estimation + reconciliation" | Audit found "cost tracking" wedge is table-stakes vs LiteLLM. Narrower position is more defensible. Honest about accuracy limits. |
| Drop runtime fallback engineering | LiveKit's FallbackAdapter handles this at plugin layer. Building VG's own duplicates functionality. Ship a docs page on the recommended composition pattern instead. |
| Substitute validation (fixtures) instead of dogfooding gate | mahimairaja explicitly opted out of dogfooding. Fixture-based testing catches obvious bugs without requiring production traffic. CHANGELOG discloses the limitation. |
| Ship Phases 1-2 minimum if timeline slips | Framing fix + genai-prices is useful standalone. Reconciliation tooling can land in v0.1.1. |
| No launch artifacts in v0.1 | Build the product right first. Launch is a separate phase, planned separately. |
| 75% test coverage minimum (existing gate maintained) | Existing CI gate. Don't lower it during a foundation rebuild. |
| Local `v0.1.0` tag, not pushed | mahimairaja decides when to publish. PyPI release is point-of-no-return. |
